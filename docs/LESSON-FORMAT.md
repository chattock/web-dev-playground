# Lesson format

Every lecture of the course gets one lesson, registered with `PG.add({...})` in
`data/sNN.js` (NN = two-digit section number). Lessons are plain JavaScript
objects. The engine lazily loads a section file when the learner opens it, and
`data/index.js` (generated by `node tools/manifest.js`) lists every lesson for
the sidebar.

## Identity fields (all kinds)

```js
PG.add({
  id: 'l202',                 // unique. New lessons: 'l' + 3-digit lecture index. Sub-lessons: 'l093b'
  index: 202,                 // Udemy lecture number (1..374) from content/manifest.txt
  sub: 'b',                   // optional: an exercise that sits BETWEEN lectures (coding exercise / quiz
                              // items in Udemy that have no lecture number). Shown as "93b".
  udemyId: 12384540,          // from content/manifest.txt (2nd column)
  minutes: 22,                // from content/manifest.txt (video length; 0 for articles)
  section: 's24',             // 's' + 2-digit section number
  slug: 'first-express-server', // lowercase-dashes, unique within the section (URL: #/s24/first-express-server)
  kind: 'node',               // build | js | react | node | sql | terminal | read | walkthrough
  project: true,              // optional badge for [Project] lectures and capstones
  title: 'Creating Our First Server with Express',  // the lecture title (without "[Project]")
  blurb: 'html string',       // 1–3 sentences: what the lecture teaches, in your own words. <code> and <b> allowed.
  tasks: ['html', ...],       // "Your task": 3–7 concrete, numbered steps the learner does HERE. Omit for read.
  quiz: [{ q, options:[4], answer: 0-based, why }],   // 2–5 questions on the lecture's key points
  explore: [{ title, note, height, html }],           // optional interactive demos (see below)
  notes: 'html',              // optional SHORT notes of your own; the full lecture notes are added automatically
  openTab: 'explore',         // optional: open this tab first
});
```

The full lecture notes (`data/notes/sNN.js`, generated from `content/notes/NNN.json`)
are attached by lecture index automatically — do not copy them into the lesson.

## Kinds and their fields

### `build` — HTML / CSS / JavaScript page with live preview
```js
files:    { 'index.html': '...', 'style.css': '...', 'script.js': '...' },   // any subset; the STARTER with TODO comments
solution: { 'index.html': '...', 'style.css': '...', 'script.js': '...' },   // same keys, finished
previewBase: 'assets/dicee/',   // optional: relative image paths in the HTML resolve under this folder
answers: 'Ada\n25',             // optional queued answers for prompt(), one per line
```
- The preview strips `<link href="style.css">` / `styles.css` and `<script src="script.js|index.js">` tags, so the course's own markup works unchanged; the panes are injected instead.
- `alert`, `console.log`, `prompt` go to the console panel. `prompt()` reads queued answers.
- Sound: `new Audio("sounds/tom-1.mp3").play()` is synthesised (tom-1..4, snare, crash, kick-bass, red, green, blue, yellow, wrong). Do not ship audio files.
- Images available (course assets are NOT copied; these are originals):
  - `assets/dicee/images/dice1.png` … `dice6.png` — use `previewBase:'assets/dicee/'` and the course's `images/dice1.png` paths.
  - `assets/drumkit/images/tom1.png, tom2, tom3, tom4, snare, crash, kick.png` — `previewBase:'assets/drumkit/'`.
  - `assets/paths/…` (cat/dog/rabbit/fish/bird pngs) for the file-paths lesson.
  - For everything else use emoji, inline SVG, CSS shapes, or `https://picsum.photos/seed/<word>/400/300` placeholders.
- Bootstrap and jQuery from the usual CDNs work; vendored copies are injected as an offline fallback automatically.

### `js` — console-first script (section 14–15 style)
Same as build with only `'script.js'` (the preview strip is small, the console is large).
Solution lectures ("… Solution"): put the finished code in `files` (so it is shown immediately) and still give `solution` (identical or improved), with tasks like "read it, run it, then try a variation".

### `react` — JSX compiled in the browser
```js
files: { 'index.jsx': '...', 'App.jsx': '...', 'components/Heading.jsx': '...', 'styles.css': '...', 'index.html': '...' },
solution: { ...same keys... }
```
- Entry: `index.jsx` (or index.js). Use ES modules: `import React from "react"; import ReactDOM from "react-dom";` plus `./App` imports. `react-dom/client` (createRoot) also works.
- Available packages: react, react-dom, react-dom/client, `@mui/icons-material/<Name>` (Add, Delete, Edit, Check, Close, Favorite, Highlight, Note, Search, Menu, Star, Send, Save), `@mui/material/Fab`, `@mui/material/Zoom`, uuid. Nothing else — keep the course's `npm` extras to those or write the component inline.
- `styles.css` is injected. `index.html` (optional) only supplies the body (`<div id="root"></div>`).
- `ReactDOM.render` works (React 18 prints a deprecation warning, shown as a warning, not an error).

### `node` — Node / Express / EJS / APIs (simulated server in the browser)
```js
files: { 'index.js': '...', 'views/index.ejs': '...', 'views/partials/header.ejs': '...', 'public/styles/main.css': '...', 'package.json': '...', '.env': '...' },
solution: { ...same keys... },
run: ['index.js'],            // entry files run in order (two servers: ['index.js', 'server.js'])
start: '/',                   // first page the built-in browser opens after the server starts
port: 3000,                   // optional, default: first port that listens
db: { seed: 'CREATE TABLE ...; INSERT ...' },   // gives `pg` a real Postgres with this data (one per run)
env: { SESSION_SECRET: 'x' },  // extra process.env
answers: 'https://example.com', // queued answers for inquirer/readline prompts
smoke: [                       // requests the validator and self-test send (status must match; default: GET start → 2xx/3xx)
  { method:'GET', path:'/', expect:200 },
  { method:'POST', path:'/submit', body:{ name:'Ada' }, expect:200 },   // body = form fields; json:{...} for JSON
  { method:'GET', path:'/secrets', expect:302 },
],
autoRun: false,               // optional: don't start on open (default starts the starter code)
```
- ESM (`import x from "y"`, `import.meta.url`) and CommonJS both work. `__dirname` is `/app`.
- Modules: express, body-parser, ejs, path, url, fs, http, os, crypto, events, util, readline, axios, pg, bcrypt, md5, express-session, passport, passport-local, passport-google-oauth2 / oauth20, dotenv, morgan, cors, qr-image, qrcode, inquirer, superheroes, supervillains, lodash, cookie-parser. Anything else throws "Cannot find module".
- `express.static("public")`, `res.render("index.ejs", data)` (views folder, `<%- include("partials/header") %>`), `res.redirect`, `res.json`, `res.sendFile(__dirname + "/public/index.html")`, `req.body` (with body-parser/express.urlencoded/json), `req.params`, `req.query`, sessions and passport all work.
- The built-in browser follows links and forms and keeps cookies. The Postman panel sends any method with Basic/Bearer auth, headers, form or JSON bodies.
- `axios` reaches: your own `http://localhost:PORT` servers; the course APIs as mocks with original data — `https://secrets-api.appbrewery.com` (`/random`, `/all?page=1` Basic auth, `/filter?score=5&apiKey=…`, `/secrets/:id` Bearer, POST/PUT/PATCH/DELETE `/secrets`, POST `/register`, GET `/get-auth-token` Basic, GET `/generate-api-key`; test user `testuser` / `secret123`, apiKey `test-api-key`, bearer `test-bearer-token`), `https://bored-api.appbrewery.com` (`/random`, `/filter?type=&participants=`), `https://v2.jokeapi.dev/joke/Any`. Other hosts are fetched for real and may fail with CORS — prefer the mocks in tasks.
- Google sign-in (`passport-google-oauth2`) shows a simulated consent page and signs in `Test User <testuser@gmail.com>`.
- `fs.writeFileSync("message.txt", ...)` and `qr.image(url).pipe(fs.createWriteStream("qr_img.png"))` show up under "files written" in the terminal. `inquirer.prompt` asks in the terminal (or uses `answers`).
- `pg`: `new pg.Client({...any config})`, `connect()`, `query(text, params)` run against the lesson's `db.seed` database. Use `$1` placeholders as in the course.

### `sql` — Postgres in the browser
```js
seed: 'CREATE TABLE ...; INSERT INTO ...;',      // run on load and on Reset
files:    { 'query.sql': '-- starter with TODOs' },
solution: { 'query.sql': '...' },
checks: [{ desc:'Two products exist', sql:'SELECT COUNT(*) FROM products', expect: 2 },
         { desc:'Rows', sql:'SELECT * FROM t', expect:{ rows: 3 } }],   // expect compares the first column of the first row
```
Statements are split on `;`. Keep seeds small (tens of rows), with data written by you (facts like country capitals are fine).

### `terminal` — shell and git simulator
```js
fs: { '/Users/you/Desktop': null, '/Users/you/Desktop/notes.txt': 'text' },   // null = folder; home is /Users/you
cwd: '/Users/you',
solution: ['cd Desktop', 'mkdir Project', 'cd Project', 'git init'],   // commands (replayable)
checks: [{ desc:'Project folder exists', test:'return fs.exists("/Users/you/Desktop/Project")' },
         { desc:'One commit', test:'const g = git("/Users/you/Desktop/Project"); return g && g.commits.length === 1' }],
welcome: 'Last login: today',   // optional first line
```
- Commands: pwd, ls [-a -l], cd, mkdir [-p], touch, rm [-r -f], cat, echo [> >>], open, mv, cp, clear, history, node file.js (small scripts), npm init / install, code .
- git: init, status, add, commit -m, log [--oneline], diff, checkout (file | branch | -b), switch, branch [-d -M], merge, rm --cached, restore, remote add/-v, push [-u origin main], pull, clone <url>. `.gitignore` is honoured. Output mimics real git.
- `test` bodies get `fs` (exists, read, isDir, list, tree), `git(path?)` → `{ branch, branches, commits:[{id,msg}], staged, unstaged, untracked, remotes, pushed, index }` or null, `shell` (cwd, history, home).

### `read` — theory, tips, admin, Q&A
No files. The main tab shows the full lecture notes. Add `quiz` where there is something to check, and `links: [{title, url, note}]` for resources the lecture points to. Keep tips/admin lessons to a blurb + a 1–2 question quiz or none.

### `walkthrough` — code shown and explained (Web3 / Motoko sections)
```js
files: { 'src/dbank_backend/main.mo': '...', 'src/dbank_frontend/index.js': '...' },   // read-only tabs
intro: 'html',                                      // how to run it for real, what it builds
steps: [{ title, text:'html', file:'src/.../main.mo', lines:[5, 9] }],   // clicking highlights the lines
```
Use it for every Web3/ICP lecture that has code. Dfx/Motoko cannot run in the browser; say so in `intro` and give the real commands.

## Explore demos (optional, any kind)
```js
explore: [{ title:'Box model dissector', height:420, note:'What to try',
  html:`<div class="knobs"><label>padding <input type="range" min="0" max="60" data-css="#box|padding|px"><span class="val"></span></label></div>
        <div class="stage"><div id="box" class="box">content</div></div>
        <pre class="readout" data-readout="#box"></pre>` }]
```
The demo iframe has helper CSS (`.knobs`, `.stage`, `.readout`, `.box`, `.tag`, `.note`) and declarative wiring: `data-css="selector|property|unit"` on inputs/selects, `data-class="selector|class"` on checkboxes, `data-readout="selector"` on a `<pre>`. Custom logic: define `window.demoInit = ({setStyle, paint}) => {...}` in a `<script>`. Demos can load `vendor/...` scripts with relative URLs. Good demos let the learner change a value and immediately see the effect — one idea per demo, 1–3 per lesson, only where it adds something a static page can't.

## Writing rules
- **Own words.** Blurbs, tasks, quiz questions, explanations and step text must be yours. Never copy sentences from the course, its transcripts, the reference repo's READMEs (they paraphrase the transcripts) or the lecture notes verbatim; restate.
- **Course code is fine.** Starter and solution code can mirror what the lecture builds (that is the point), cross-checked with the reference repo `../angela-yu-reference/Section NN - .../NN.MM - .../`. Strip personal touches from that repo (author footers, names, hard-coded credentials, real API keys). Fix its bugs; the notes JSON lists known ones.
- **No course media.** Do not copy images, sounds, fonts or downloads from the course or the reference repo. Use the assets listed above, emoji, inline SVG or picsum placeholders.
- **Starters are unsolved.** Replace the parts the learner must write with `<!-- TODO: ... -->` / `// TODO: ...` comments that say what goes there. Keep the scaffolding the course gives. Every task in `tasks` must be doable in the editor.
- **Match the lecture.** The task is the lecture's exercise or project (same names, routes, variables, ports). If a lecture has no exercise, pick the kind that best lets the learner try what was taught: a tiny `build`/`js`/`node` with 2–3 tasks for coding lectures, `read` for talk-only lectures. "Solution" lectures: `files` = finished code, tasks = understand/vary.
- **Projects** (`project: true`): a fuller starter, 4–7 tasks, a complete solution. Capstone instruction articles: a scaffold + tasks from the brief (own words), solution = a reasonable complete implementation.
- **Quiz**: 4 options, one correct, `why` explains in one sentence. Ask about concepts, not trivia.
- Use `(Extra)` nowhere in lessons — that convention is only for the notes.

## Validate
```bash
node tools/validate.js s24        # structure + runs node/terminal/sql/react solutions
node tools/validate.js s24 -v     # list passing lessons too
```
Fix every ✗. The validator runs the solution (so a `node` solution must start, serve the `smoke` requests and log no errors; a `terminal` solution must satisfy its own checks; `sql` solution + checks must pass). Do not run `tools/manifest.js` or `tools/build-notes.js` — they are run once at the end.
